# hackera.online

Marketing site for **Hackera**: a catalog of 250 digital services in 20 categories
(web development, SEO, marketing, design, cybersecurity, AI and more), plus a
"Website as a Service" subscription package.

- **Live site:** https://hackera.online (EN) · https://hackera.online/bg/ (BG)
- **Stack:** plain HTML, vanilla JS and hand-written CSS. No framework, no bundler,
  no `npm install`. The files in this repo are exactly what gets served.
- **Static pages:** the SEO pages under `services/` and `bg/uslugi/` are generated by
  `build.js` and committed to the repo.

## Structure

```
index.html              English homepage (/)
bg/
  index.html            Bulgarian homepage (/bg/)
  uslugi/               Generated Bulgarian catalog: hub, 20 categories, service pages
services/               Generated English catalog: hub, 20 categories, service pages
content/                Hand-written per-service text for build.js (services.json)
css/
  tokens.css            Design tokens (colors, fonts)
  style.css             All site styles
js/
  data.js               Service catalog data (bilingual): categories and services
  app.js                App logic, renders everything into #root
  agent.js              AI assistant widget (mounts into #agentMount in the hero)
  icons.js              Self-hosted icon set (no CDN)
admin.html              Operator console for live chat (Firebase sign-in required)
login.html              Sign-in page for admin.html
build.js                Static page generator (Node), see "Regenerating pages"
sitemap.xml             Generated by build.js
llms.txt                Generated by build.js
robots.txt, favicon.svg, og-image.png
_headers                HTTP headers for the host
wrangler.jsonc          Cloudflare config: serves the repo root as static assets
.assetsignore           Files excluded from the Cloudflare upload
CNAME                   Custom domain file (GitHub Pages)
```

## How the site works

- `js/app.js` renders the whole page into `#root` and re-renders on every state
  change (language switch, cart, filters). The table of contents at the top of the
  file lists every section (hero, catalog, pricing, FAQ, ...).
- The language is decided by the URL: `/` is English, `/bg/` is Bulgarian.
- Catalog entries live in `js/data.js`. The "Learn more" modal text per category
  lives in `CATEGORY_DETAIL` inside `js/app.js`.
- Forms (service request, notifications) are sent through FormSubmit to the
  contact email. The subscription button uses the PayPal JS SDK.
- Each `index.html` contains a crawlable static snapshot inside `#root`. It is
  replaced by the interactive app once `app.js` loads.

## Regenerating pages

Run from the repo root (Node.js required):

```powershell
node build.js
```

It reads `js/data.js`, the `CATEGORY_DETAIL` block in `js/app.js` and the optional
`content/services.json`, then rewrites:

- `services/` and `bg/uslugi/` (deleted and rebuilt every run)
- `sitemap.xml` and `llms.txt`
- the `<!--CATEGORIES-->` block in `index.html` and `bg/index.html`

Commit all of those afterwards. Cloudflare only serves the files; it does not run
the build.

**Thin-content rule:** a service page is indexable only if `content/services.json`
has hand-written text for it in both languages. All other service pages get
`noindex, follow` and are left out of `sitemap.xml` and `llms.txt`.

**Do not remove or rename:**

- the `<!--CATEGORIES-->` ... `<!--/CATEGORIES-->` markers in `index.html` and `bg/index.html`
- `const CATEGORY_DETAIL = {` and `function getCategoryDetail` in `js/app.js`
  (`build.js` finds the data between them)

## Local preview

The pages use absolute paths (`/css/style.css`, `/js/app.js`), so `file://` will not
work. Serve the folder over HTTP:

```powershell
python -m http.server 8080
```

Then open http://localhost:8080/ (EN) or http://localhost:8080/bg/ (BG).

## Deployment

Push to `main`. Cloudflare publishes the repo root as static assets
(see `wrangler.jsonc`). Editing files directly on github.com works the same way.

## Live chat

The AI assistant (`js/agent.js`) can hand a visitor over to a human. The operator
answers from `admin.html`, which uses Firebase Authentication and the Firebase
Realtime Database. Access goes through `login.html`.
